# ADR 0012：反馈音效在准备前设置音频属性

## 状态

已接受。

## 背景

应用的反馈声音需要在番茄钟结束、固定提醒和倒计时到达时可靠播放。当前实现使用 `MediaPlayer.create()` 创建内置或本地音效，再调用 `setAudioAttributes()`；但 `create()` 会自动完成 `prepare()`，属性设置已经晚于播放器准备。在部分 Android 版本或音频路由下，这可能导致音频属性未生效，甚至播放器启动失败，系统铃声回退也不一定存在。

## 决策

- 统一通过手动创建 `MediaPlayer` 播放文件或 `android.resource` URI。
- 在 `setDataSource()` 和 `prepare()` 之前设置 `USAGE_NOTIFICATION_EVENT` 与 `CONTENT_TYPE_SONIFICATION`。
- 内置提示音、本地导入音效和系统铃声继续按“自定义文件 → 用户选择的系统铃声 → APK 内置提示音 → 系统默认通知音”的顺序回退。
- 通知渠道保持静音，由应用直接播放反馈；这样用户选择的音效不会被渠道创建时的旧声音配置覆盖，通知权限也不会阻止声音/振动反馈本身。

## 备选方案

### 继续使用 `MediaPlayer.create()` 后修改属性

- 实现简单，但违反音频属性必须在准备前设置的生命周期要求，跨设备行为不稳定。
- 不采用。

### 引入 Media3/ExoPlayer

- 能力更完整，但首版反馈音效是小型本地提示音，引入额外依赖和生命周期管理没有必要。
- 暂不采用；若未来增加长音频、播放队列或音频焦点管理，再单独评估。

## 后果

- 内置和导入音效共享同一条可验证的播放器构造路径，减少无声回归风险。
- `prepare()` 仍是同步操作，但音效文件限制为 5 MB，适合在提醒接收器的后台协程中完成。
- Android 系统的通知音量、静音/勿扰模式、蓝牙路由和厂商省电策略仍可能影响最终听感，必须在实体设备上验收。
