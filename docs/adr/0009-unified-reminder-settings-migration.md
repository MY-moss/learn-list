# ADR 0009：统一提醒配置与旧版迁移

## 状态

已接受。

## 背景

早期版本把每日进度提醒和安静时段存放在 DataStore 的全局字段中。当前提醒系统已经使用 `ReminderEntity` 保存每一条提醒的类型、时间、星期、启用状态和安静时段；旧字段继续被保存和导出，却不会影响实际排程，容易造成“设置看似存在但不生效”。

## 决策

- 新运行时设置不再暴露或写入旧的全局提醒字段；每日进度提醒只通过 `SUMMARY` 类型的统一提醒实体管理。
- 首次启动、导出备份前会检查旧字段。若本机还没有 `SUMMARY` 提醒，则按旧值创建一条提醒，并保留启用状态、时间和安静时段；已有统一提醒时不重复创建。
- 迁移采用“先创建成功，再清理旧键”的顺序，并用一次性标记和互斥锁避免重复迁移；创建失败时保留旧键，下一次启动重试。
- 旧备份仍读取 `summaryReminderEnabled`、`summaryReminderMinutes`、`quietStartMinutes` 和 `quietEndMinutes`，导入后转换为统一提醒；新备份不再写出这些死配置字段。
- 合并导入不覆盖本机已有的每日进度提醒；替换导入在恢复数据后仅在没有统一提醒时补建旧版提醒。

## 备选方案

### 继续保留全局字段并让排程同时读取

拒绝。两套配置会产生优先级冲突，也无法表达多个每日进度提醒，和现有提醒编辑界面重复。

### 直接删除旧键，不做迁移

拒绝。虽然旧字段当前不生效，但旧版本用户的提醒意图仍应在升级和备份导入时得到保留。

## 后果

- 每日总览提醒拥有与项目提醒一致的编辑、启用/停用和排程行为。
- 新备份结构更单一；旧备份仍可安全导入。
- 用户升级后的首次启动会多一次本地迁移操作，但不需要联网，也不会创建重复提醒。
